소노리 — API 키는 어디로 가나요

소노리에는 서버가 없습니다. 여러분이 넣은 Gemini API 키는 이 기기에 저장되고, Google 의 Gemini API 로만 전송됩니다. 개발자는 키를 받을 수도, 볼 수도 없습니다.

확인할 수 있는 사실

  • 저장 위치 — iOS: Keychain(암호화). Apple Watch 를 페어링해 설정 동기화를 쓰면 워치의 보안 저장소에도 사본이 저장됩니다(기기 간 직접 전달, 서버 경유 없음). Android: Android Keystore 가 관리하는 키(기기가 지원하면 하드웨어 보호)로 AES-256/GCM 암호화, 앱 전용 저장소, 클라우드 백업 제외.
  • 키가 실리는 연결은 하나뿐 — generativelanguage.googleapis.com(Google Gemini API). 실시간 통역은 WebSocket 연결의 URL 매개변수(?key=)로, iOS 의 AI 브리프 요청은 x-goog-api-key 헤더로 보냅니다. 통역 중이 아닐 때 키가 쓰이는 경우는 iOS 에서 AI 브리프를 직접 생성할 때뿐입니다(Android 에는 아직 그 기능이 없습니다).
  • 키가 실리지 않는 연결 — 인앱 브라우저가 여는 웹페이지, ‘무료 키 받기’로 여는 Google AI Studio, iOS 의 원격 기능 플래그(GitHub Gist 공개 파일), 그리고 이 안내 페이지. 이 연결들에는 키가 포함되지 않습니다.
  • 키는 개발자에게 오지 않습니다 — 앱에는 Firebase 오류 보고·사용 통계가 들어 있지만(개인정보 처리방침 참조) 그 어디에도 키·오디오·자막은 실리지 않습니다. 광고 SDK 는 없습니다.
  • 직접 확인 — 네트워크 프록시(Charles, Proxyman, mitmproxy 등)를 기기에 물리고 통역을 켜 보세요. iOS 에서는 프록시 인증서를 신뢰시키면 요청 내용까지 보이고, 키(AIza…)가 포함된 요청은 generativelanguage.googleapis.com 으로 가는 것뿐입니다. Android 정식 빌드는 사용자가 설치한 인증서를 신뢰하지 않아 내용은 열리지 않지만(그때는 연결이 실패합니다), 앱이 어느 호스트에 접속하는지는 그대로 보입니다.

키 안전하게 쓰기 — 3단계

우리를 믿지 않아도 안전하도록, 키 자체에 울타리를 치세요.

  • 1. 소노리 전용 키를 만드세요. Google AI Studio 에서 새 키를 만들고 다른 앱·스크립트와 공유하지 마세요. 문제가 생겨도 이 키 하나만 폐기하면 됩니다.
  • 2. 결제를 연결하지 마세요(무료 등급). 무료 등급 프로젝트의 키는 남용되더라도 청구가 발생하지 않습니다. 필요하면 Google Cloud 콘솔에서 키를 Generative Language API 로만 제한하세요.
  • 3. 언제든 폐기하세요. Google AI Studio 에서 키를 삭제하면 그 즉시 어디서도 쓸 수 없습니다. 앱 설정의 ‘키 삭제’는 기기(및 페어링된 워치)에서 지웁니다.

Sonori — Where your API key goes

Sonori has no servers. The Gemini API key you enter is stored on this device and is sent only to Google's Gemini API. The developer cannot receive or see it.

What you can verify

  • Storage — iOS: the Keychain (encrypted); with a paired Apple Watch and settings sync on, a copy also lives in the Watch's secure store (device-to-device, no server). Android: AES-256/GCM under an Android Keystore-managed key (hardware-backed where the device supports it), app-private storage, excluded from cloud backup.
  • The only connection that carries the key — generativelanguage.googleapis.com (Google Gemini API). Live interpreting sends it as the WebSocket URL's ?key= parameter; the iOS AI Brief request sends it in the x-goog-api-key header. Outside a session the key is used only when you generate an AI Brief yourself on iOS (Android has no such feature yet).
  • Connections that never carry the key — pages the in-app browser loads, Google AI Studio opened by "get a free key", the iOS remote feature flags (a public GitHub Gist file), and this page.
  • The key never reaches the developer — the app does carry Firebase crash reporting and usage statistics (see the privacy policy), but neither the key, audio nor transcripts are ever part of them. There are no ad SDKs.
  • Check it yourself — put a network proxy (Charles, Proxyman, mitmproxy) on the device and start interpreting. On iOS, trusting the proxy certificate shows request contents: the only requests containing your key (AIza…) go to generativelanguage.googleapis.com. Release builds on Android don't trust user-installed certificates, so contents stay sealed (the connection fails instead), but the hosts the app connects to are still visible.

Using your key safely — 3 steps

  • 1. Make a key just for Sonori in Google AI Studio and don't share it with other apps or scripts. If anything goes wrong, revoking that one key is enough.
  • 2. Don't attach billing (free tier). A free-tier key cannot generate charges even if abused. Optionally restrict it to the Generative Language API in the Google Cloud console.
  • 3. Revoke any time. Deleting the key in Google AI Studio invalidates it everywhere at once; "Delete key" in the app removes it from the device (and a paired Watch).
